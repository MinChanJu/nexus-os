# 깃허브 컨벤션

이 문서는 NexusOS 프로젝트에서 사용하는 GitHub 컨벤션에 대해 설명합니다. 이 컨벤션은 이슈, 브랜치, 커밋 메시지, PR 작성에 대한 일관된 규칙을 제공합니다. 모든 방식은 [git-flow](https://danielkummer.github.io/git-flow-cheatsheet/index.ko_KR.html) 워크플로우를 기반으로 합니다.

## 이슈 컨벤션

이슈 이름은 다음과 같은 형식을 따릅니다:

```txt
<이모지> [<이슈타입>] <이슈제목>
```

| 이슈 타입 | 이모지 | 설명             |
| --------- | ------ | ---------------- |
| Epic      | 🦄     | 대규모 기능 추가 |
| Story     | 🧩     | 사용자 스토리    |
| BugFix    | 🐞     | 버그 수정        |
| HotFix    | 🚨     | 긴급 버그 수정   |
| Refactor  | ♻️     | 코드 리팩토링    |
| Release   | 🚀     | 배포 준비        |

### Epic 이슈 템플릿

```markdown
## 🦄 개요

이슈에 대한 간단한 설명
(ex: 새로운 사용자 대시보드 기능 추가)

## 💬 관련 문서

(관련된 문서나 링크를 추가)
```

### Story 이슈 템플릿

```markdown
## 🧩 개요

이슈에 대한 간단한 설명
(ex: 사용자가 회원 가입을 할 수 있도록 기능을 구현한다.)

## ✅ 작업 내용

- [ ] GitHub OAuth 연동
- [ ] 회원 가입 폼 구현
- [ ] 이메일 인증 기능 추가
- [ ] 사용자 데이터베이스 저장

## 🎯 완료 조건

- [ ] 사용자가 정상적으로 회원 가입을 할 수 있다.
- [ ] 이메일 인증을 통해 계정 활성화가 가능하다.

## 💬 관련 문서

(관련된 문서나 링크를 추가)
```

### BugFix 이슈 템플릿

```markdown
## 🐞 개요

이슈에 대한 간단한 설명
(ex: 회원 가입 시 이메일 인증이 정상적으로 작동하지 않는 문제 수정)

## 🔧 재현 방법

(버그를 재현하는 단계별 설명)

1. 회원 가입 페이지로 이동
2. 이메일 입력 후 가입 시도
3. 이메일 인증 링크 클릭 시 오류 발생

## 🛠️ 수정 내용

- [ ] 이메일 인증 로직 수정
- [ ] 관련 테스트 케이스 추가

## 💬 관련 문서

(관련된 문서나 링크를 추가)
```

### HotFix 이슈 템플릿

```markdown
## 🚨 개요

이슈에 대한 간단한 설명
(ex: 긴급 보안 패치 적용)

## 🔧 재현 방법

(긴급 수정이 필요한 문제에 대한 설명)

1. 특정 상황에서 보안 취약점 발생

## 🛠️ 수정 내용

- [ ] 보안 패치 적용
- [ ] 관련 테스트 케이스 추가

## 💬 관련 문서

(관련된 문서나 링크를 추가)
```

### Refactor 이슈 템플릿

```markdown
## ♻️ 개요

이슈에 대한 간단한 설명
(ex: 회원 가입 모듈 코드 리팩토링)

## 🔧 리팩토링 내용

- [ ] 코드 구조 개선
- [ ] 불필요한 코드 제거
- [ ] 성능 최적화

## 💬 관련 문서

(관련된 문서나 링크를 추가)
```

### Release 이슈 템플릿

```markdown
## 🚀 개요

이슈에 대한 간단한 설명
(ex: 버전 1.0.0 배포 준비)

## 💬 관련 문서

(관련된 문서나 링크를 추가)
```

## 브랜치 네이밍 컨벤션

브랜치 이름은 다음과 같은 형식을 따릅니다:

```txt
<타입>/<이슈번호>-<이슈제목> // 이슈 제목은 되도록 영문 소문자와 하이픈(-)으로 작성
```

| 브랜치 타입 | 설명             |
| ----------- | ---------------- |
| feature     | 새로운 기능 개발 |
| bugfix      | 버그 수정        |
| hotfix      | 긴급 버그 수정   |
| refactor    | 코드 리팩토링    |
| release     | 배포 준비        |

- Epic 이슈의 경우 브랜치는 생성하지 않습니다.
- Story 이슈의 경우 feature/ 이슈 타입을 사용합니다.
- BugFix 이슈의 경우 bugfix/ 이슈 타입을 사용합니다.
- HotFix 이슈의 경우 hotfix/ 이슈 타입을 사용합니다.
- Refactor 이슈의 경우 refactor/ 이슈 타입을 사용합니다.
- Release 이슈의 경우 release/ 이슈 타입을 사용합니다.

## 커밋 메시지 컨벤션

커밋 메시지는 다음과 같은 형식을 따릅니다:

```txt
<타입>: <이슈번호> <커밋제목>

<본문>

<꼬리말>
```

| 커밋 타입 | 설명                               |
| --------- | ---------------------------------- |
| feat      | 새로운 기능 추가                   |
| fix       | 버그 수정                          |
| docs      | 문서 수정                          |
| add       | 새로운 에셋 추가                   |
| remove    | 불필요한 에셋 제거                 |
| refactor  | 코드 리팩토링                      |
| test      | 테스트 코드 추가 및 수정           |
| setting   | 환경 설정 관련 변경                |
| deploy    | 배포 관련 변경                     |
| chore     | 간단한 주석 제거 및 기타 변경 사항 |

## PR 컨벤션

PR 제목은 다음과 같은 형식을 따릅니다:

```txt
[<타입>] <이슈제목> (<이슈번호>)
```

- PR 타입은 브랜치 타입과 동일하게 사용합니다.
  - 예시: [feature] 회원 가입 기능 구현 (#42)

### PR 템플릿

```markdown
> PR 제목\
> [<타입>] <이슈제목> (<이슈번호>)
>
> 예시\
> [feature] 회원 가입 기능 구현 (#42)

## #️⃣ 연관된 이슈

> close #<이슈번호> (예: close #42)

## 📄 작업 내용

> 이번 PR에서 작업한 내용을 간단히 요약합니다.
>
> - GitHub OAuth 연동
> - 회원 가입 폼 구현
> - 이메일 인증 기능 추가

## 📸 스크린샷 (필요할 경우)

> 변경된 UI나 참고 이미지가 있다면 스크린샷을 첨부합니다.

## 💬 관련 문서 (필요할 경우)

> 관련된 문서나 링크가 있다면 작성합니다.

## 🫡 참고 사항

> 작업에 걸린 시간: <시간> (예: 3시간)\
> 추가로 참고할 사항이 있다면 작성합니다.
```
